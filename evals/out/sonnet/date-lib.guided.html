January 31 plus one month is February 28.

calends is a JavaScript library for parsing, formatting and adding to calendar dates. Months stop at their last day instead of spilling into the next one, the date you pass in is never changed, and "2026-11-12" is November 12 in every time zone.

API

Six functions, all exported by name. Every function that returns a date returns a new Date and leaves its arguments alone. All dates are in the local time zone.

import { parse, format, add, startOf, diff, daysInMonth } from "calends";

parse

parse(text: string): Date

Reads YYYY-MM-DD, optionally followed by a space or T and HH:mm or HH:mm:ss. A date-only string means midnight local time. Throws a RangeError for text it cannot read and for days that do not exist, such as 2026-02-30.

format(parse("2026-11-12"), "D MMM YYYY")
→ "12 Nov 2026"

format

format(date: Date, pattern?: string): string

Replaces the tokens listed above. The default pattern is YYYY-MM-DD. Month and weekday names are English.

format(parse("2026-03-04"), "ddd, DD/MM/YY")
→ "Wed, 04/03/26"

add

add(date: Date, amount: { years?, months?, weeks?, days? }): Date

Years and months keep the day number when the target month has it, and otherwise stop at that month's last day. Weeks and days are plain calendar days. Negative numbers subtract. Time of day is kept.

format(add(parse("2024-02-29"), { years: 1 }))
→ "2025-02-28"

startOf

startOf(date: Date, unit: "day" | "week" | "month" | "year"): Date

Returns midnight at the start of the unit. Weeks start on Monday.

format(startOf(parse("2026-11-12"), "week"))
→ "2026-11-09"

diff

diff(a: Date, b: Date, unit: "days" | "weeks" | "months" | "years"): number

Whole units from b to a. The result is positive when a is later and negative when it is earlier. A part-completed unit counts as zero.

diff(parse("2026-12-25"), parse("2026-11-12"), "days")
→ 43

daysInMonth

daysInMonth(date: Date): number

The number of days in the month the date falls in, leap years included.

daysInMonth(parse("2028-02-01"))
→ 29

Compared with Date

Four cases where the built-in Date surprises people, and what calends does instead.

CaseBuilt-in Datecalends
Add a month to January 31 d.setMonth(d.getMonth() + 1) lands on March 3, because February 31 overflows. add(d, { months: 1 }) gives February 28, or 29 in a leap year.
Read a date-only string new Date("2026-11-12") is midnight UTC, so getDate() returns 11 in time zones west of Greenwich. parse("2026-11-12") is midnight local time, so getDate() returns 12 everywhere.
Add a day d.setDate(d.getDate() + 1) changes d itself, and every other variable that points at it. add(d, { days: 1 }) returns a new date. d is untouched.
Find the start of the week getDay() counts Sunday as 0, so Monday-first weeks need arithmetic. startOf(d, "week") returns that week's Monday.
